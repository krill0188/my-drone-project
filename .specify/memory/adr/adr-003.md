# ADR-003: TensorRT + ONNX Runtime Dual Inference Engine

## Status
Accepted

## Context
AI inference runs on Jetson Orin (TensorRT) and Snapdragon (ONNX Runtime). Different models have different optimization requirements:
- Critical perception (obstacle detection): < 10ms latency, maximum accuracy
- Mission perception (landing assessment): < 50ms latency, good accuracy
- Fault detection: < 100ms latency, can batch process

Different hardware backends have different optimization paths.

## Decision
Implement a **unified inference abstraction layer** with dual backend support:

**TensorRT (Primary - Jetson Orin)**
- FP16/INT8 quantization for YOLOv8n, MobileNetV3
- TensorRT engine caching for fast startup
- CUDA streams for async inference
- DLA (Deep Learning Accelerator) for background tasks

**ONNX Runtime (Fallback - Snapdragon/Generic)**
- CPU/GPU/HTP execution providers
- Graph optimization, constant folding
- Session caching for fast startup

**Unified API** (`ModelRuntime`):
```cpp
class ModelRuntime {
    virtual bool load(const ModelConfig& config) = 0;
    virtual bool infer(const Tensor& input, Tensor& output) = 0;
    virtual bool inferBatch(const std::vector<Tensor>& inputs, std::vector<Tensor>& outputs) = 0;
    virtual InferenceProfile getProfile() const = 0;
};

class TensorRTRuntime : public ModelRuntime { ... };
class OnnxRuntime : public ModelRuntime { ... };
```

**Model Selection Logic**:
- Critical models (obstacle detection): TensorRT preferred, ONNX fallback
- Mission models (landing): TensorRT preferred, ONNX fallback
- Batch models (fault detection): ONNX preferred

## Consequences
### Positive
- Hardware-agnostic inference API
- Optimal performance per platform
- Graceful degradation (TensorRT → ONNX)
- Model format standardization (ONNX as interchange)

### Negative
- Dual maintenance burden (TensorRT + ONNX)
- Model conversion pipeline complexity (ONNX → TensorRT engine)
- Version compatibility (TensorRT/ONNX Runtime versions)

### Neutral
- ONNX as canonical model format
- TensorRT engine as deployment artifact
