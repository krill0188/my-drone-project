# ADR-005: GTSAM-based VIO + UWB Fusion

## Status
Accepted

## Context
Visual-Inertial Odometry (VIO) provides high-frequency, drift-prone pose estimates. UWB provides low-frequency, absolute position with cm-level accuracy but sparse updates. GPS is unavailable indoors/jammed. Need robust pose estimation for:
- Formation flying (cm-level relative accuracy)
- Precision landing (cm-level absolute accuracy)
- Indoor/GPS-denied operation

Single sensor cannot provide continuous, accurate, drift-free pose.

## Decision
Adopt **GTSAM-based factor graph optimization** for VIO + UWB fusion:

**Factor Graph Structure**:
```
Variables:
  - X_t: Pose at time t (SE(3))
  - V_t: Velocity at time t
  - b_g, b_a: IMU biases
  - p_uwb_i: UWB anchor positions

Factors:
  - IMU Preintegrated: X_t, V_t, b_g, b_a → X_{t+1}, V_{t+1}
  - Visual Reprojection: X_t, landmarks → pixel measurements
  - UWB Range: X_t, p_uwb_i → measured range
  - Prior: X_0, V_0, b_g, b_a
  - Loop Closure: X_t, X_{t-k} (visual)
```

**Fusion Strategy**:
- IMU @ 200Hz: High-rate propagation (preintegrated)
- Visual @ 30Hz: ORB-SLAM3 features → pose constraints
- UWB @ 10Hz: Absolute position anchors
- GPS @ 10Hz: When available, global frame

**Implementation**: GTSAM 4.2+ with iSAM2 (incremental smoothing)
- Incremental updates at IMU rate
- Batch re-optimization every 10 visual frames
- Marginalization for fixed-lag smoothing (500ms window)

**Output**: 200Hz pose estimate (SE(3) + velocity + biases) with covariance

## Consequences
### Positive
- Mathematically optimal fusion (maximum a posteriori)
- Consistent covariance propagation
- Handles asynchronous, multi-rate sensors naturally
- Loop closure corrects drift
- Marginalization enables fixed-lag (bounded compute)

### Negative
- Computational complexity: O(n^3) for batch, O(n) incremental
- Tuning: noise models, outlier rejection thresholds
- GTSAM dependency (C++ template-heavy, compile time)
- Initialization complexity (visual + IMU alignment)

### Neutral
- Open source (BSD), well-maintained
- ROS 2 integration via gtsam_ros
