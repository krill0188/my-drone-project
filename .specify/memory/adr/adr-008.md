# ADR-008: QGC Plugin + Web Dashboard Hybrid GCS

## Status
Accepted

## Context
Ground Control Station (GCS) needs:
- **Mission Planning**: Waypoints, polygons, inspection targets, CBBA allocation
- **Real-time Monitoring**: Formation, health, mesh QoS, safety events
- **Post-Flight Analysis**: Coverage, CDF, AI timeline, QoS reports
- **Platform Support**: Desktop (Linux/Windows/macOS), Tablet, Mobile
- **Extensibility**: Plugins, custom widgets, Python scripting

Existing options:
- **QGroundControl (QGC)**: Mature, PX4-native, desktop-only, C++/Qt/QML
- **Mission Planner**: Windows-only, ArduPilot-focused
- **Custom Web**: Full control, but re-implementing basic GCS features

## Decision
Adopt **QGC Plugin + Web Dashboard Hybrid** architecture:

**QGC Fork (Core Flight Operations)**:
- Base: QGC 4.2+ (LGPLv3)
- Plugins (C++/QML):
  - `SwarmMissionPlanner`: Waypoints, search polygons, inspect targets, CBBA preview
  - `SwarmMonitor`: Real-time formation, health, mesh QoS, safety events
  - `PostFlightAnalyzer`: Coverage heatmap, CDF, AI timeline, QoS reports
- Python Backend Bridge (JSON-RPC):
  - Log analysis (FFT, condition check, PID tuning)
  - Antenna tracker, mission scripting
  - MAVLink ↔ Python bridge

**Web Dashboard (React 18 + TypeScript + Vite)**:
- Live View: Real-time map, fleet summary, safety alerts, ESTOP/RTL/HOLD
- Replay: Timeline scrubbing, synchronized map replay, chart replay
- Analytics: Fleet KPIs, radar comparison, formation CDF, AI timeline, QoS matrix
- Reports: HTML/PDF/JSON generation, templates
- Mobile/Tablet responsive, PWA support

**Communication**:
- QGC ↔ Companion: MAVLink 2.0 + Custom Swarm Messages
- Web Dashboard ↔ Backend: WebSocket (ROS 2 bridge) + REST API
- Python Backend ↔ QGC: JSON-RPC over stdin/stdout

## Consequences
### Positive
- **QGC**: Reuses mature flight operations (arming, RTL, params, logs)
- **Web**: Modern UX, mobile access, custom analytics, no C++ compilation
- **Python Bridge**: Reuses Mission Planner analysis tools (FFT, PID, antenna)
- **Separation**: Flight-critical (QGC) vs. Analytics (Web)
- **Extensibility**: Plugin architecture on both sides

### Negative
- Dual codebases: QGC (C++/QML) + Web (React/TS)
- Python bridge: JSON-RPC latency, process management
- Dual deployment: QGC desktop + Web server
- Sync: QGC ↔ Web state synchronization

### Neutral
- MAVLink 2.0 as canonical protocol
- Shared swarm_msgs for ROS 2 ↔ MAVLink translation
- QGC plugin API stability
